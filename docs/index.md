## 这个站点在做什么

它想验证一件很朴素的事：**写完 Markdown 推送上去，网站就自己更新了**，中间不需要人登录服务器、不需要手工上传文件。

整个链条只有四步：

- `docs/` 里放 Markdown 源文件
- 推送时 GitHub Actions 自动装依赖、构建
- 构建产物上传成 artifact
- Pages 把它发布成一个公开网址

## 一点实践体会

真正跑一遍才发现，这个流程里最容易出问题的不是写文档，而是**边界条件**：

1. **构建报错的往往不是正文**。`mkdocs build --strict` 会把警告也当失败，第一次跑就卡在 `site_url` 少写结尾斜杠这种小事上。
2. **"部署成功"和"网站已更新"不是同一时刻**。Actions 里 deploy 变绿之后，Pages 发布还要再等十几秒，刷新太快会看到旧页面，误以为没生效。
3. **触发条件写窄了容易漏**。工作流只监听 `docs/**` 和 `mkdocs.yml`，所以改 `report/` 下的报告不会触发部署 —— 这不是 bug，是设计，但要心里有数。

这几条以前只是读过文档里的字，自己踩过一次才算真记住。
